# PR 03 — Results, disclosure gates and transparent interpretation

## Why

A survey without findings gives little learning value. But publishing live group outcomes during collection could bias new visitors, and tiny cells can expose individual response values.

## Changes

- `results.html` and `assets/results.js`: group sizes and publication status; after closure and >=20 saved responses per group, show means, mean difference, response histograms, approximate confidence interval and limitations.
- Results API is already implemented in PR 01, so no more public backend endpoints are needed.
- Results link is shown **only after** a response is confirmed by the server (or in explicitly labeled demo mode).
- Public group outcomes remain hidden until the study owner manually closes the v2 study (`V2_STATUS='closed'` in `backend/Code.gs`) and redeploys that Apps Script version.
- A study that ends too small remains private at the group level: it can still be discussed with properly aggregated owner-side analysis after assessing disclosure risk.

## Acceptance

- While `V2_STATUS='collecting'`, public page shows total and group completion counts but no mean, median or effect estimate.
- With status closed but a group below 20 responses, public group WTP statistics remain hidden.
- With closed and sufficient groups, real aggregates display correctly and non-numeric values are rejected.
- Charts make no claim of revenue impact or proven anchoring.

## Important

The 20-per-group display gate is **not** a statistical sample-size recommendation. A proper sample-size calculation requires an effect size, spread and stopping rule. The simple normal confidence interval is illustrative/descriptive; use the offline reproducible analysis before publishing conclusions.
